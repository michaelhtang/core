# Arcade (proof of concept): games where the server decides the score

Three games share one module: **Bill Dash**, **Diversify** and **Debt Snake** (sections below). Everything in "As built" applies to all unless it says Bill Dash.

Realtime play that students expect from a game, without trusting the browser. The browser plays a fixed-step, integer-only game and records its inputs; the server replays those inputs through the **same file** with a seed it chose, and the score is whatever the replay says.

## As built

**Files.** `modules/arcade/index.js` (routes, table, throttle; the `GAMES` registry holds each game's core, title, blurb and the event a verified finish emits), `modules/arcade/ui/games/billdash-core.js` (the whole game, shared by server and browser), `ui/games/billdash.js` (canvas drawing, input, 30 ticks/s loop), `ui/arcade.js` + `arcade.css` (the Arcade building). Enabled in both courses, right after `exchange` and before `savings` (pinned in `test/db.test.js`; the module has no tick, the slot is just fixed).

**Flow.**
1. `POST /api/arcade/start { game: 'billdash' | 'diversify' }`: season must be active (409 otherwise), at most 12 starts an hour per student for each game, counted separately so using up one game never blocks another (429 naming the game and the minutes left; in memory, `options.arcade.startsPerHour`). Writes an `arcade_runs` row (random 128-bit hex id, server-chosen 32-bit seed, `open`); any older open round of that student becomes `superseded`. Returns `{ session, game, seed, ticks: 1350 }`.
2. The browser plays and records `[[tick, mask], ...]`: a change list, one entry each time the held mask changes. Bill Dash mask bits: 1 left, 2 right, 4 action (masks 0-7). Diversify adds 8 rebalance (masks 0-15): the server takes the limit from the core's `C.MASK_MAX`, 7 when a core has none.
3. `POST /api/arcade/finish { session, inputs }`. There is **no score field** (an extra `score` is ignored). The server checks the session is this student's, `open`, in the current season and under 10 minutes old, validates `inputs` (array of at most 2000 `[tick, mask]` integer pairs, ticks strictly increasing and below 1350, masks 0 to the game's maximum; a malformed body is a 400 and does not burn the round), replays outside any transaction, then in one transaction runs `UPDATE ... WHERE status = 'open'` and checks `changes`, so a double finish is a 409 and cannot count twice. Response: `{ score, best, plays, new_best, ticks, hearts, stats, leaderboard }` for Bill Dash; for a game whose core exports `report(state)` (Diversify) `stats` is that report and there is no `hearts`. `best`, `plays` and `leaderboard` are for the round's own game.
4. Wall-time guard: if less than 40% of the ticks the replay actually played (a round ends early at zero hearts) has elapsed since `start`, the run is stored `rejected` with `flag = 'fast'` and the finish is a 422. It is a lazy-bot-batch guard, never an input to the score.
5. After a verified finish with at least one recorded input the module emits `module.arcade.played` for Bill Dash and `module.arcade.played_diversify` for Diversify, both `{ playerId, worldId, game, score }` (Today's `done.event` cannot filter on a payload field, and an event name allows `_` but not `-`, so each game has its own name and a round of one never completes the other's errand). Today's errand `play-bill-dash` ("Play a round of Bill Dash", 50 cents x price index, energy 1, priority 6) listens for it and completes once, idempotently, only when it is among that day's three picks. No stress, wage, ledger or promotion effect.
6. `GET /api/arcade/state` (no writes): `{ world_active, games: [{ key, title, blurb, best, plays, ticks, leaderboard }], leaderboard, my_best }`. Each game has its own `leaderboard` (top 10 of the student's class: rank, username, best, mine) and best; the top-level `leaderboard` and `my_best` are Bill Dash's again, kept for older callers. Board and best are queries over `status = 'finished'` runs of that game in the current world. One open round per student across both games; the 12-starts-an-hour throttle is counted per game (since 2026-11-20; before, both games shared one 12).

**Table** `arcade_runs` (`mod:arcade:001_runs`): `id, player_id, world_id, game, seed, score, ticks, status (open | finished | rejected | expired | superseded), flag, started_at, finished_at`. Inputs are not stored.

**The replay check.** `replay(seed, inputs)` in the core walks 0..1349, holds each recorded mask until the next change, calls `step`, and stops when the round is over. The core has no imports, no `Math.random`, no `Date`, no floats and no division (a test scans the source), so any engine gives the same answer. A full replay costs well under 1 ms (a test asserts < 20 ms).

**Bill Dash constants** (one table, `C` and `KINDS` at the top of the core): 30 ticks/s, 1350 ticks, 4 lanes, 3 hearts, start cash 60, cash cap 150, paycheque +60. Fall speed 28 to 56 sixteenths of a pixel per tick, spawn gap 26 to 12 ticks (+0-5 jitter), both ramping linearly. Pay zone: item top 64-95 px; at 96 an unpaid bill is late (score -20, one heart). Bills: rent 60, insurance 35, card 25, phone 15 (cost = score value; +25% when paid in the top half of the zone). Spawn weights per 100: rent 8, phone 17, card 16, insurance 12, paycheque 33, SALE 14. A bill without enough cash stays and costs 3 points plus a 12-tick lockout; a SALE tag costs 20 cash for nothing; an empty stamp costs a 9-tick lockout. If cash is under 30 and no paycheque is on screen, the next spawn is a paycheque. Lane change cooldown 3 ticks, stamp cooldown 4. Final score = running sum, floored at 0. RNG draws (kind, lane, jitter) are always taken in that order.

**How to play and the legend (Bill Dash, 2026-11-19).** The game's card has a "How to play, and what everything means" section (open until the student has finished a round, `plays` 0): nine numbered steps and a tip, written from the constants above (`UI.billdash.steps` and `tip` in `ui/arcade.js`; change the numbers there whenever `C` or `KINDS` change). Beside it, and beside the canvas while playing, is a legend: what falls (each item with its price), the bill border colours, the pay zone, the red line, your lane, hearts, the pop-up words (+18, +$60, LATE, NSF, -$20) and the side panels. Its pictures are drawn by `swatch()` in `billdash.js`, the same drawing code as the game (`item()` now calls a shared `tile()`; the screen is pixel-for-pixel unchanged). A container 660 px or wider puts the legend in a 234 px column on the right; narrower (a phone) puts it under the touch pads, and the canvas keeps its old scale. Starting a round scrolls the canvas into view, because the Play button can sit below the how-to. Checked in headless Chromium at 1280x900 (x4), 1366x650 (x3) and 375 px (x2, no sideways scroll), with one full round finished and verified by the server; not on a real phone or by a student. No game rule, score or pay changed.

**Tuning evidence** (bots, 60 seeds; humans untested): a no-input round ends at about 6 s with 0; a sloppy bot (30-tick reaction, pays what it cannot afford, buys SALE tags) averages about 290; a careless bot about 520; a greedy careful bot about 830; the best seeds for that bot reach 1000-1100 (no human-play data).

## Teacher panel ("Arcade")

`GET /api/arcade/teach` (teachers only; a student gets 403, nobody 401) and `modules/arcade/ui/teach.js`. For each class the teacher reads (`k.players.classesFor`, so never another teacher's class) and the current season only: `finished` (verified rounds), `rejected` with `rejected_by` (the stored `flag`, today only `fast`), `players` (distinct students with a verified round), `best` (`{ score, username, game }`, ties go to whoever got there first) and `recent` (the last 10 verified rounds: pseudonym, game, score, `at` ms). Those are the class totals over both games; each class also has `games: [{ key, title, finished, rejected, rejected_by, players, best, recent }]`, the same fields once per game, and the panel shows the class line then one section per game. Read only, pseudonyms only, SQL aggregates per class and game (the `arcade_runs_board` index). Verified in the browser with the demo seed: a round that ended in 245 ticks scored 0 and showed as finished; an instant finish showed as rejected.

His choice ("all games, errands follow"). ## Not verified / known ceilings

- A determined player can compute a perfect-play input log offline (the seed is returned at `start`) and submit it. Rewards are capped and non-compounding (one 50-cent errand a day, a class board), so the stakes are low. Hiding the seed until the end is not possible with this design: the client needs it to play.
- No stress, wage or ledger effect yet. Stress has a month off-by-one trap (`bump` in `modules/stress/index.js` keys on the event's own month); wire it only after reading that.
- No SSE or live push for the student board: it refreshes when you open the building or finish a round. (The Today and Around town cards on the home screen do refresh live, docs/live.md.)
- No feed post ("X scored N"); feed has no posting service, only listeners.
- The teacher panel does not show the "Play a round of Bill Dash" errand count: that needs today's table, which arcade does not read (it would take a today service).
- The errand shows wherever the `arcade` module is loaded for any course (today filters templates by `k.modules.has`, not per course); with both courses enabling it that is exact, but a config that enables it for one course only would offer the errand to the other.
- Browser-checked at 375 px (canvas scales x2 and stays crisp, touch pads 64 px tall, no CSP violation) and at desktop (x4), but not on a real phone, and only with synthetic key and pointer events. The in-app browser pane was hidden, so `requestAnimationFrame` was throttled and the check ran with a `setTimeout` shim. Whether a casual human lands in "a few hundred" is untested.
- A hidden tab ends the round (it does not count); a round abandoned this way stays `open` until the next start supersedes it.

## Diversify (second game)

A 45 second realtime pixel game about diversification and risk. Same architecture as Bill Dash: `ui/games/diversify-core.js` is import-free, integer-only and deterministic (the test scans it: no imports, floats, `Math.random`, `Date` or division; there is a tiny shift-and-subtract `idiv`), the browser plays it, records `[[tick, mask], ...]` and the server replays it; the client never sends a score. 30 ticks a second, 1350 ticks, mask bits 1 left, 2 right, 4 drop, 8 rebalance (at most 2000 entries).

**Rules.** Four baskets: CASH (a HISA), BONDS, INDEX (an index fund), STOCK (one company). About 37 paycheques ($1.50, $2.00 or $2.50) arrive in the wolf's hands roughly once a second; the wolf starts over CASH and moves one basket per press (4 tick cooldown). Drop lets the coin go now; otherwise it lets go by itself after 24 ticks. It lands 9 ticks later in the basket the wolf was over when it let go, so doing nothing puts everything in cash. Rebalance moves a quarter of the biggest basket into the smallest (90 tick cooldown). Eight headlines hit the baskets during the round: RATES UP (bonds -7%, index -2%, stock -3%, cash +1%), RATES DOWN (bonds +5%), CRASH (index -20%, stock -32%, bonds +2%), PRICES UP: CASH BUYS LESS (cash -6%, bonds -3%; a real-terms effect, a HISA balance does not fall in dollars, so every number is in buying power), STOCK JUMPS (+30%), SCANDAL (stock -40%), BOOM (index +9%, stock +14%). Between headlines every basket drifts each half second (per step, in 1/16384: cash +8, bonds +20, index +34, stock +48) with seeded noise (bonds +-24, index +-90, stock +-220; cash none).

**Same market for everyone.** The step noise, the headline ticks and kinds and the paycheque schedule are all drawn when the game is created, from three separate seeded streams in a fixed order. A player's inputs cannot change them, so every player of a seed sees the same headlines at the same ticks (a test asserts it).

**Score** = 200 + (the total minus what the same paycheques would have ended at in cash alone, landing when they landed, with cash's own growth and headlines) / 4 + a spreading bonus (up to about 600 for an even split, from the Herfindahl index of the four baskets sampled every half second once the total passes $10, averaged over the round) minus the worst drop (peak to trough of the total, in tenths of a percent, 1 point each); floored at 0. Money put in earns nothing by itself, so doing nothing (every paycheque into cash) scores only the 200 floor minus a small drop, about 140-200. The excess over cash is negative when a mix does worse than cash. A coin still in the air at the end is lost. All constants are in the `C`, `BUCKETS` and `EVENTS` tables at the top of the core.

**Calibration** (bots, 200 seeds, `seed = n x 7919`; humans untested):

| bot | mean score | median | 5th to 95th percentile |
| --- | --- | --- | --- |
| even split, rebalances when one basket passes 30% | **753** | 737 | 358 to 1159 (max 1424) |
| all cash (also exactly what doing nothing does) | **157** | 140 | 140 to 200 |
| all-in single stock | **283** | 0 | 0 to 1412 (max 2660) |

The all-in stock bot beat the spread bot on **21 of 200 seeds (10.5%)**; cash beat the spread bot on 1 of 200 and the spread bot beat cash on 199. The spread bot's worst drop averages 10.5% against 36% for all-in stock. A mixed bot (10% cash, 20% bonds, 40% index, 30% stock) averages 709 and all-in index 311 (it earns no spreading bonus, and one basket is one basket even if it is an index fund). Over the 200 seeds all-in stock and the spread bot end with about the same total (about $80): the difference is the drop penalty and the bonus. Good rounds sit around 1000-1400; lucky seeds go higher.

**Ceilings.** A greedy hindsight bot (each coin goes where the replay says it scores best, later coins split evenly, no rebalancing; computed offline over 20 seeds) averages about 970 against 843 for the even-split bot on the same seeds, best seed 2160. Because the seed is returned at `start`, a determined player can compute such a log offline; the stakes are one 50-cent errand a day and a class board, as for Bill Dash.

**Debrief.** The finish response's `stats` is the core's `report(state)`. All numbers are integers and the screen shows exactly them: whole-number percents per basket (floored, the remainder going to the biggest so they add up to 100), the worst drop (`ddPct`, `loss`), money put in, `total`, `cashEnd` (what cash alone would have ended at), `evenEnd` (an even four-way split of the same paycheques, no rebalancing), the score parts (`floor`, `gain`, `bonus`, `penalty`), the headlines that hit, rebalances, and one sentence chosen by rules in `lesson()`. The worst-drop fields record the baskets at the lowest point of the drop, so `topBucket` and `topPct` are the composition when the drop was deepest, and `evenLoss` is how much the even split lost over the same peak-to-trough stretch. Each sentence is chosen only by comparing numbers in the report and says "this round" or "in this game": concentration (a drop of 7% or more, 60% or more of the money in one basket at the lowest point, and the even split really lost at least $1.00 less); mostly cash (50% or more: "ended at" only if the total reached the money put in, "buying power fell" only if it did not, "when prices rose" only if that headline came, and the even-split comparison only if it really ended higher); a heavy basket that worked (60% or more in one basket, small drop, total at least the money put in and above cash alone); well spread with a drop under 10%; otherwise the worst drop. A test runs 200 seeds x three bots and asserts none of these contradicts the report. The wording is plain, gives no advice and no gambling language, and uses Canadian terms (HISA, bonds, index fund, single stock). The lesson is rule-based; the market is a compressed game (a round is a few years of drift in 45 seconds), not a forecast, and no human has played it yet.

**Errand.** `play-diversify` ("Play a round of Diversify", 50 cents x price index, energy 1, priority 6) is done by `module.arcade.played_diversify`; it needs a Diversify round and a Bill Dash round does not count for it (or the reverse). For both games the event is emitted only when the replayed input log has at least one entry: a finish with `inputs: []` still gets its server score but earns no errand (otherwise an 18-second wait would be enough to farm it).

**Input and screen.** 160x120 canvas scaled by a whole number; keyboard arrows or A/D, Space or S/Down drop, R or Shift rebalance; touch pads Left, Right, Drop, Rebalance (64 px tall). The pixel font and the wolf come from `billdash.js` (it now exports `wolf`; nothing else in it changed). The loop is Bill Dash's fixed-step accumulator with the capped catch-up (at most 250 ms and 8 ticks per frame). A hidden tab or a closed page abandons the round and nothing is sent (exactly Bill Dash's behaviour), so there is no keepalive finish for this game. Verified in the in-app browser (first version of the score) at desktop (x4) and 375 px (x2) with a `requestAnimationFrame` -> `setTimeout` shim and synthetic key and pointer events, with the server score equal to a local replay of the recorded inputs; the reworked score and debrief were re-checked at desktop only (one finished round, server score 504 equal to the local replay, debrief text consistent with its numbers; the harness stubbed `document.hidden` because the pane was hidden); a teacher view on `localhost` listed both games (the class line counts finished rounds and players only; each game section shows its own best). Not tested on a real phone or by a human.

## Debt Snake (third game)

Rules, modes and the core's API are in `docs/debtsnake.md` (Mr. Tang's choice, 2026-11-20); the core is `ui/games/debtsnake-core.js`, with its own test. This section is how it is wired into the Arcade.

**Files.** `ui/games/debtsnake-core.js` (the game), `ui/games/debtsnake.js` (canvas, input, loop, and the pictures for the legend and the mode buttons; its `MODES` list is the name and one-line rule of each mode, and a test pins its keys to the core's `MODE_KEYS`), `ui/arcade.js` and `arcade.css` (tile, card, picker, result), `ui/thumbs/debtsnake.jpg`, `scripts/debtsnake-thumb.mjs` (renders that picture with the game's own drawing code), `test/arcade-debtsnake.test.js`.

**What differs from the other two games.**
- **Options.** `POST /start { game: 'debtsnake', opts? }`: a core that exports `parseOptions` gets the optional `opts`; an invalid one is a 400 with the core's own message (nothing is started and an open round is not superseded). The normalized options and the core's `optionKey` are stored on the run and returned (`opts`, `mode`). `/finish` replays with the stored options (`replay(seed, inputs, opts)`); a client `opts`, `mode` or `score` in the body is ignored. Bill Dash and Diversify have no `parseOptions`: their start, finish and rows are as before (`opts` and `mode` stay null).
- **Per mode.** Best, plays and the class board are per mode key (speed, board and coins do not split them). `/finish` returns `mode` and that mode's `best`, `plays`, `leaderboard`. `GET /state` gives the Debt Snake entry the classic numbers by default, or those of `?game=debtsnake&mode=<key>`, plus `mode` and `modes: { key: { best, plays } }` for every mode the student has finished. `GET /board?game=debtsnake&mode=<key>` (read only, default classic) returns `{ game, mode, best, plays, leaderboard }`; an unknown or non-canonical key is a 400. The key must be exactly what `optionKey` gives (`etransfer+latefees`; in a URL write the `+` as `%2B`).
- **Migration** `004_run_opts`: `arcade_runs.opts TEXT`, `arcade_runs.mode TEXT`, and an index on `(world_id, game, mode, status, player_id)`. Migrations 001-003 are untouched.
- **Switch and errand.** `debtsnake` is a key in `GAMES`, so the teacher panel has a switch and a section for it, and `/start` and `/board` answer 403 when it is off. `todayFacts` gives `debtsnakeOn`. Errand `play-debt-snake` ("Play a round of Debt Snake") has the same `reward_cents`, `energy` and `priority` as `play-bill-dash` (Mr. Tang's decision; a test pins it), is done by `module.arcade.played_debtsnake`, and (like the others) is emitted only when the replayed log has at least one input. Today picks 3 errands a day, and four arcade errands now share priority 6, so on a day one of them can miss a student's three; the older tests that read an errand drop FinWord in their test world so their pick is certain.

**Screen.** 168 x 184 logical px (top bar, a board of 10 x 9, 15 x 13 or 21 x 17 squares, a footer with the mode and best), drawn at 4x so the snake glides with round corners and a tapered tail from `view().progress` plus the fraction of the next tick; the font, walls and items stay blocky. Dark slate board, teal body, gold head, coins and bills. The Feel list of the spec: the mouth opens at `near <= 2`, the next coin is on the board the same tick, payment burst and "-$100", tail red for the last 8 moves and new segments sliding out ("+$100"), "DEBT FREE" flash once, best per mode, no sound. Fine Print dims every square outside 2 of the head and 1 of each item. Input: arrows or WASD, swipe on the board, an on-screen d-pad on phones (shown at 720 px and narrower, or on a touch device). Each press becomes its own one-tick pulse in the order made (a gap tick between two of the same key), so the core's rising-edge turns see what was pressed and the log is `[[tick, mask], ...]` with every press held for one tick. Space starts a new round from the result screen (it does not restart a round in progress, so a slip cannot use up one of the 12 starts an hour). A hidden tab ends the round and it does not count, as in the other games.

**Card.** How to play (nine steps from the spec's numbers: change them in `UI.debtsnake.steps` when the core changes), a legend of every item, pop-up word and the top bar, a picker with a button for every mode (small drawn icon, name, one-line rule, best), **Mix** (pick several; classic is not mixable), **Surprise me** (three different random modes chosen in the browser before `/start`; a choice of game, never a reward), Speed, Board (default small) and Coins, then Play. The best and class board shown are those of the chosen mode (`/board`). The result shows the server's score, the core's `report`, and that mode's board.

**Verified.** Headless Chromium against a local server with a demo class: a classic round played by a scripted browser bot ending in a crash, one Mix round, one Fine Print round, and a 375 px phone round, each finished and verified by the server, with no console errors (screenshots were saved to the project folder, not the repo). Tests: `node --test test/arcade-debtsnake.test.js test/arcade.test.js test/arcade-switches.test.js`.

**Not verified.** Not on a real phone or with a real swipe (touch and swipe were exercised with synthetic events only), not by a student, no sound by design. Only the modes a round happened to touch were seen on screen; the other icons and items are drawn by the same code but were not each looked at in play. The legend texts for `expiring` (blink), `hiddenfees` and `creditcheck` follow the spec, not a played round of each. Whether human scores land in a sensible range is untested (the core's bots are its own test). As for the others, a determined player can compute a perfect input log offline from the returned seed; the stakes are one 50-cent errand a day.

## FinWord (daily word game)

**Only live lessons.** `wordle-words.js` keeps the full list as `ALL_WORDS`; the game uses `WORDS`, the entries whose term and meaning are in that server's `modules/learn/content/<course>.json`. On `release-pilot` (2026-11-20) that drops FinTech Marketplace (10 FinTech 10 words) and The Venture and The Investor (30 of 45 FinTech 20/30 words) until those lessons ship; the day-to-word order then shifts, and a game in progress keeps its stored word.

A Wordle-style game, one puzzle a day per course (student-facing name `WORDLE_TITLE = 'FinWord'` in `wordle-words.js`; never call it anything else to students). No score, no leaderboard, no season needed. Today's errand `play-finword` ("Play today's FinWord", 50 cents, same shape as the other two) listens for `module.arcade.played_finword`, emitted once when a game ends, won or lost alike (payload `{ playerId, worldId, game: 'wordle' }`, identical either way, so copying an answer earns nothing extra); no event while no season is active, and never on a 400/409. Arcade's `todayFacts` gives `finwordOn`.

**Word.** `modules/arcade/wordle-words.js` (server only: it is deliberately NOT under `ui/`, which `/m/arcade/` serves to browsers) holds `WORDS = { fintech10: [...], fintech2030: [...] }`, entries `{ word, term, meaning, section }` taken from the `terms` of `modules/learn/content/fintech10.json` / `fintech2030.json` (term and meaning verbatim, section = that unit's section title). A word is a one-word term of 4-9 letters or one word of a longer term that carries its meaning. Today's entry is `list[(days since 2026-01-01) mod length]` using `k.clock.today()` (Edmonton), the player's class course only. A player without a class or in a course with no list gets 400. 90 FinTech 10 words, 45 FinTech 20/30 words; `REVIEW-wordle.md` lists them in play order for Mr. Tang. Order puts different sections on neighbouring days (FinTech 10 always; 20/30 has 4 neighbours in the same section because "The Investor" is more than half the list: 25 Investor, 15 Taxpayer, 5 Venture; the tax lessons have only about 28 terms and few give a good word).

**Rules.** Board width = the word's length, 6 guesses, any A-Z string of the right length (no dictionary, `ponytail:` in the code), standard marking (`mark()`: greens first, then yellows by remaining counts) as `hit | near | miss`. Hint from the start: the section title. At the end (won or lost) the response adds `answer`, `term`, `meaning`; before that no response or error holds the answer.

**Server.** Migration `003_wordle`: `arcade_wordle (player_id, day, course, word, guesses JSON, status open|won|lost, finished_at)`, primary key `(player_id, day)`; the row is made at the first guess and keeps the word, so a list edit never changes a game in progress. `GET /api/arcade/wordle` and `POST /api/arcade/wordle/guess { guess }` return `{ title, day, length, section, max, guesses: [{ guess, marks }], status, stats }` (+ answer fields at the end): wrong length or non-letters 400 (no guess used), finished 409, switched off for the class 403. Stats: played, won, current and best streak (consecutive days won; the current streak survives an unplayed today), guess distribution 1-6. FinWord is not in `GAMES` (no core): `/state` adds a `kind: 'daily'` entry (with `today: new|open|won|lost`), `/switch` accepts `wordle`, `/teach` lists it in `switches`.

**UI.** Tile `wordle` in `TILES` with its own `go()` -> `wordle()` in `ui/arcade.js`: board (each tile has an aria-label like "B, right spot"), on-screen and physical keyboard, hint, status line, end card (answer, term, meaning, errand note), stats, three "how to play" steps. Fits 375 px with 9-letter words. Thumbnail `ui/thumbs/wordle.jpg` is a screenshot of the real mid-game board. Test: `test/arcade-wordle.test.js`.

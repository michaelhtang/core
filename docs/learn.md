# Learning Road (`learn`)

A road of short lessons in front of the economy. A level is a few reading **cards**, then **questions**; a question missed on the first try comes back at the end until every one is right. A finished level pays a small amount of real in-game money, once. Pattern from `replica/recon.md` (clean-room: the pattern only; the wording, questions, art and code are ours; the mascot is the DAA Wolf).

Wave 1 ships the engine and one unit, **Money & You > Gross pay to net pay** (8 levels, 40 cards, 72 questions, from Mr. Tang's lessons 5 and 6), plus five empty "coming soon" units so the road shows where it goes. Everything with a pay number in it agrees with `modules/jobs/payroll.js` (a test recomputes it).

## As built

**Files.** `modules/learn/index.js` (the module definition, routes, teacher query), `reads.js` (course and progress reads, open units), `daily.js` (streak, daily review), `league.js` (ranked leagues), `tiers.js` (the ten ranks), `attempts.js` (reward, start/answer/finish, bots), `migrations.js` (tables), `content.js` (loader and boot check), `content/fintech10.json` (the course), `content/REVIEW.md` ("Facts Mr. Tang must confirm"), `ui/` (`learn.js` the building, `road.js`, `player.js`, `figures.js`, `card.js` the home card, `teach.js`, `teachmath.js`, `learn.css`). Enabled in both courses right before `today` (pinned in `test/db.test.js`; no tick). A course with no content file (FinTech 20/30 in wave 1) gets the building and an empty road, no home card and no errand.

**The server owns every answer.** `/state` and `/start` carry cards and questions with no `answer`, no `why`, no `working`, no `miss`, no `traps`, no `check` (a test walks every key of both payloads). `/answer` judges one question and returns the feedback for what was chosen; the right answer is returned (`correct_value`) only when the student has given it. A wrong number or wrong tap returns the question's `miss` line, never the working.

**Locks.** A level opens when the level before it in the unit is done; a unit opens when every earlier unit that has levels is done; the first level of the first unit is open. Units with `levels: []` are teasers (`soon`) and never block anything. A locked `/start` is a 403 naming the level to finish first.

**An attempt** is one row of `learn_attempts` (open while `finished_at` is NULL), unique per student, world and level. `/start` resumes the open attempt instead of making a new one, so leaving and coming back cannot reset what counts as a first try. Its `state` is `{ first: { questionId: { v, ok } }, solved: [ids], queue: [ids to fix] }`. The FIRST answer to a question decides `ok`; later answers only change `solved`. Answering out of order, answering again after it is solved (judged as already solved, nothing changes) and restarting change nothing. `/finish` is refused (409) until every question is solved.

**First completion vs replay.** The first `/finish` of a level in a world writes `learn_progress` (first try count, questions, paid cents), the per-question first answers into `learn_answers`, pays the reward and emits the event, all in one transaction. A replay (`practice: true`) pays nothing, writes no answers and only raises `best_first_try`. `first_try` of the first completion stands.

**Rate limit.** At least 300 ms between two answers from one student (429), in memory per kernel (`options.learn.answerGapMs` changes it).

**Content directory.** `options.learn.contentDir` (a path) makes a kernel read its courses from that directory instead of `modules/learn/content/`, loaded once per directory and checked the same way (a bad directory or file throws the same errors). Not set: unchanged. The default load still happens at import, so a malformed real file still fails boot. Card pictures still resolve against `public/art/learn/`. Tests use it with `test/learn-fixture.js` (the real file cut down to the pay unit) so engine tests do not depend on how much content exists.

## Reward

`cents = round(min(100 + 10 x first-try answers, 200) x price index)`. A 9-question level with every answer right first time pays 100 + 90 = $1.90 at index 1.00; the cap ($2.00) is reached at 10 first-try answers. Paid once per level per world as one ledger txn of kind `learn.reward`, from the `mint` (like a Today errand) into chequing. Today's errand `learn-level` ("Finish a level on the Learning Road", 50 cents x price index, priority 6) is offered only when the student has an open level (`learn.todayFacts` -> `hasOpenLevel`) and is completed by `module.learn.completed`.

Economy guard (`node scripts/sim.mjs --months=60`, 300 bots): errand + quest + learn cash must stay under 1% of lifetime net pay. The line now prints the total and the split. Before (no learn): `errand + quest cash $17492.18 = 0.039%`. After: `errand + quest + learn cash $19750.68 (errands and quests $17793.41, Learning Road $1957.27) = 0.044%`. The sim's bots alternate between the two courses, so the 150 FinTech 10 bots each finish all 8 levels and earn about $13 once; $15.20 (8 x $1.90) is the most the road can pay a student in wave 1.

With all six units of section 1 (44 levels, 2026-11-10) the same run prints `errand + quest + learn cash $29240.93 (errands and quests $18154.71, Learning Road $11086.22) = 0.066%`: each FinTech 10 bot earns about $74 once for the whole section, and the most the road can pay a student at index 1.00 is 44 x $1.90 or less a level. Still far under the 1% limit.

With all four sections (140 levels, 2026-11-10) the same run prints `errand + quest + learn cash $30558.88 (errands and quests $18442.92, Learning Road $12115.96) = 0.069%`. The most the whole road can pay one student at index 1.00 is $266.70 (each level pays $1.00 plus $0.10 a first-try answer, capped at $2.00), against $500.00 of starting money: a tuning choice for Mr. Tang if that is more or less than he wants.

With section 5 (152 levels, 2026-11-11) the run prints `errand + quest + learn cash $30184.61 (errands and quests $18068.65, Learning Road $12115.96) = 0.068%`. The Learning Road figure does not move because the sim's bots play at most two levels a month for 60 months (120 levels at most) and section 5 starts at level 141, so the run does not measure section 5. By the pay rule the whole road can now pay one student $290.10 at index 1.00 ($23.40 of it from section 5). Section 6 (levels 153 to 167) is not measured either, for the same reason; with it the whole road can pay one student $319.50 at index 1.00 ($29.40 of it from section 6).

## Content format

`content/<course id>.json`, checked at boot by `content.js` (`checkCourse`): any problem throws `modules/learn/content/<file>: <path>: <why>`, for example `sections[0].units[1].levels[0].questions[3].options[2].why: every option needs a why of 1-300 characters`.

```
course  { id (= the file name), title, sections[] }
section { id, title, blurb, units[] }
unit    { id, title, blurb, outcome_codes[], levels[] }          levels: [] = a "coming soon" teaser
level   { id (stable, never reused), title, kind: "lesson", learn: [2 short lines], cards[4-6], questions[7-10], go?: { building, label } }
card    { text (<= 320 chars), figure? | image? }   (a card has a figure or an image, not both)
```

Rules the check enforces: unique ids across the course; every answer in range; a `choice` has 3-4 options and EVERY option has a `why`; the longest option is at most 2 x the shortest + 20 characters (length must not give the answer away); no "all/none of the above"; a question label is 2-4 words; a level's right choices are not all in the same position; a `point` question's figure is a `line` or `bars` chart. `go` puts a button on the completion screen that opens a building (level 7 sends the student to the Job Centre).

Pictures (`image`, on a card and on a unit): `{ src, alt }`. `src` is `folder/name.webp` (lowercase letters, digits, `-`) relative to `public/art/learn/` and the file must exist (boot fails with the content path if not); `alt` is required, 5-120 characters, what is pictured in plain words. A unit's image is its banner (1200x675, 16:9); a card's is 640x640. FinTech 10 unit 2 has a banner and 32 card pictures in `public/art/learn/ft10-s1-u2/` (`l<level>c<card>.webp`; the prompts are in `design/art/ft10-u2-prompts.tsv`). `/state` sends each unit's `image` (null when none), `/start` sends the card images, and the home card's data carries the current unit's `image`. In production new files need a server restart (`VDAA_DEV=1` rebuilds the file map per request).

Figures (`figure`): `table { title, columns[], rows[][] }`, `paystub { title, lines: [{ label, cents, role: earn | deduct | net, ytd? }] }` (both real tables), `bars { title, unit, bars: [{ label, value }] }`, `line { title, unit, points: [{ label, value }] }` (inline SVG built with DOM calls; `unit` is `$` (values in cents), `%` or `hours`).

## How to add a unit or a level

1. Write the levels in `content/<course>.json` under the unit (fill in a teaser's `levels`, or add a unit). Use fresh, stable ids (`ft10-s1-u3-l1`); never renumber a level that students have finished, because progress rows are keyed by the id.
2. Put every pay figure through `payroll.js` (write the answer from `payStub`, add a `check`). Put a fact you cannot source in `content/REVIEW.md` with its question id; write the question so it does not depend on an unsourced number.
3. Run `node --test test/learn.test.js`. It reports the exact path of the first bad item.
4. A new course is a new file named after the course id (`fintech2030.json`); its students get the road automatically.

## Open units

A teacher chooses which units are open to each class. Tables (migration `003_open`): `learn_open_set` (a row = the class has a setting: class, when, by whom) and `learn_open_unit` (class, unit id; the open units). No `learn_open_set` row = every unit is open (nothing changes); a row with no units = everything closed. The list is explicit, so a unit added to the course later is closed for a class that has a setting until the teacher ticks it.

**Route.** `POST /api/learn/open-units { class_id, units: [unit ids] }` sets the whole open set (an empty list closes everything); `{ class_id, all: true }` clears the setting. 404 a class you do not teach; 400 a unit id not in the class's course, a unit with no levels, a duplicate, or neither `units` nor `all`. Audited as `learn.open_units`. Returns `{ class_id, open_units }` (`null` after clearing). `/teach` carries per class `open_units` (`null` or the ids) and `open_sections` (sections with their units that have levels) for the form.

**The rule, on the server.** A unit with levels that is not open is **closed**. `/start`, `/answer` and `/finish` on a level of a closed unit are 403 `That unit is not open for your class yet.` before anything is read or written: no pay, no progress, no XP, no streak; no practice replay of a finished level and no continuing an attempt left open. Among the open units the usual order rule counts only open units: the first open unit's first level is open, and an open unit unlocks when every earlier open unit that has levels is done. "Next" (`/state`, the home card, the Today errand fact `hasOpenLevel`, the bots in `simulate()`, the completion screen) is the first unfinished level in the open units; with none open there is no next level. `/state` gives closed units `status: "closed"` and their levels `locked`. The road says "Closed" on a closed unit's row (and on a section row when all its units with levels are closed), or "No units are open for your class yet." when nothing is open.

**What stays.** Progress recorded in closed units stays and still counts in totals, the league, the daily review (it reviews finished levels wherever they are) and the teacher's numbers. **Changing the setting mid-season** takes effect on the next request; nothing is deleted or re-paid; closing a unit and reopening it brings its progress back into the order rule. Reads still never write. A stored unit id the content no longer has is ignored.

**Teacher panel.** Per class, "Units open to this class": a status line, checkboxes grouped by section (each with Open all / Close all), Save, and "Open everything (clear this setting)".

## Daily loop (wave 2b)

Decisions are in `replica/recon.md` section 14. A day is **kept** by finishing a NEW level (first completion) or the daily review. No money anywhere in this: `rewardFor` and the ledger are untouched; the review pays XP only. Everything is per (player, world); only an active world counts.

**Tables** (migration `002_daily`): `learn_streak (player_id, world_id, streak, best, freezes, last_day)`; `learn_days (player_id, world_id, day, xp, frozen)`, a row = that day was kept (`frozen = 1`: a freeze covered it, 0 XP); `learn_review (player_id, world_id, question_id, box, due_day)`; an index `learn_attempts_pl` for the finished-review lookup. The migration back-fills `learn_review` from `learn_answers` (box 0 if the first answer was wrong, else 2, due at once).

**Streak rules** (`streakView(row, today)` read-only, `keepDay(row, today)` for a kept day; both pure and exported, tested from a case table). `gap` = whole days strictly between `last_day` and `today`. Same day: nothing changes. `gap == 0`: alive, keep makes streak + 1. `0 < gap <= freezes`: alive; keep spends `gap` freezes, writes those days as frozen, streak + 1 (frozen days are not counted in the number). Bigger gap: lost (shown as 0 with 0 freezes); keep makes streak 1, freezes 0. After any keep, if `streak % 7 == 0` then `freezes = min(2, freezes + 1)`. The day is `k.clock.today()` (Edmonton), so it turns over at midnight. Reads never write: `/state` and the home card compute the shown streak from the stored row and today's date; the row is written only when a day is kept, and the day row is an upsert, so `simulate()` calling `finish()` many times in a day is safe.

**XP.** First completion of a level: `10 + first_try`, keeps the day. Replay of a finished level: 0 XP, does not keep the day. Daily review: `5 + first_try`, keeps the day.

**Daily review.** A question enters `learn_review` when its level is first completed (first try wrong: box 0, due tomorrow; right: box 2, due in 4 days). Intervals by box `[1, 2, 4, 8, 16]` days. `/start` with `level_id: "review"` resumes today's open review or picks up to 5 ONCE (due first, then `due_day`, `box`, `question_id`; if fewer than 5 are due the not-yet-due ones fill in, so a review exists every day once any level is done; ids no longer in the content are skipped) and stores them in the attempt state (`qids`); the attempt row is `learn_attempts.level_id = 'review:<day>'`. 409 once today's review is done ("Come back tomorrow") and 409 before any level is finished. The payload has `cards: []`, `max_reward_cents: 0`, `level.review: true`, and each question has `from` (the title of its level); the same `publicQuestion` and `check()` keep answers server side. `/answer` 404s a question outside the set. `/finish` is 409 until all are solved, then sets each question's box from its FIRST answer (right: box + 1, max 4, due in `INTERVALS[box]` days; wrong: box 0, due tomorrow), adds XP and keeps the day. It writes no ledger, `learn_progress` or `learn_answers` row. An open review from an earlier day is left alone (it is neither resumed nor blocks today's).

**`/state` `daily`**: `{ today, streak, best, freezes, kept_today, at_risk, xp_today, xp_week, week: [7 x { day, state: kept | frozen | missed | today | future | none }], review: { state: ready | done | locked, count } }`. A day a held freeze would cover shows as `frozen`; days before the first kept day are `none`. **`league`**: see "Leagues". **Home card** data adds `daily: { streak, kept_today, freezes, review }`. **Teacher** `/teach` adds per class `roster: [{ username, rank, streak, best, kept_7, xp_week }]` (named `roster` because `students` is already the class size).

**UI.** Road header: streak chip, freeze chips, a 7-dot week strip, the "Keep your streak" line when at risk, and the review row; the league under the road (rank name and badge, the rows, a marker on the promote and demote rows). The review plays in the same player with no cards. The completion screen shows XP, First try and Day streak from the response's `daily`, plus "Streak kept" and the freeze line. The Today card's own chip is now labelled "Errand streak" (a different, class-day count).

**Limits.** The review set is fixed when started and not re-picked if content changes under it. Streak and week come from the server clock only. Not browser-checked in wave 2b's build.

## Leagues

Ranked leagues replace the weekly class league. Ten ranks, lowest first, in `tiers.js`: Iron, Bronze, Silver, Gold, Platinum, Emerald, Diamond, Masters, Grandmasters, Challenger. A rank is a name and a badge; no money is attached (`rewardFor`, the ledger and pay are untouched). Students only; teachers are in no league. All numbers are in one object, `LEAGUE` in `league.js`: `GROUP_MAX` 30, `PROMOTE` 10, `PODIUM` 3, `DEMOTE` 5. The Leagues tab lists the whole group (up to 30 rows; until 2026-11-19 it showed only the top 10 plus the student's own row).

**Week.** Monday to Sunday by `k.clock.today()` (Edmonton), the same `mondayOf` as the streak. The ranking is the XP in `learn_days` for that week.

**Tables** (migration `004_league`): `learn_rank (player_id, world_id, tier)` (no row = Iron); `learn_league_group (world_id, week, player_id, tier, grp, to_tier)`, the group each student was in for a week (`week` = its Monday; `to_tier` is NULL until the week is settled); `learn_league_done (world_id, week)`, a row = that week is settled.

**Groups.** The league is per world, so every class in the world is in it. The first `/state` of a week builds the groups for every student of the world: students of the same rank, `ceil(n / 30)` groups, sizes as even as possible, order from the hash (sha256) of world id, week start and player id; no random numbers and no clock. The groups are stored, so they do not change all week. A student who first appears mid-week joins the group of their rank with the fewest members (lowest number on a tie), or a new group when every group is full (30).

**Settling.** The first `/state` of a world after a week has ended settles it (every unsettled past week that has group rows, oldest first), in one transaction, once (`learn_league_done`). `/state` is the only write on that path; when nothing is due it is two indexed reads. In each group, sort by week XP, then username. Up: the top `PROMOTE`, but at most half the group (`floor(size / 2)`, at least 1), so any group of 20 or more moves 10 up; everyone tied with the last student inside the line also moves up; never with 0 XP. **Podium:** the top `PODIUM` (3) of those move up two ranks instead of one, but never more places than the promotion zone (a group of 4 promotes 2, and both jump two), plus everyone tied with the last podium place (Mr. Tang chose this 2026-11-19 so Challenger, 9 moves from Iron, is reachable in one semester: weekly with one move a week, only 8 results landed before classes end Jan 15; on the podium every week it is 5 weeks). Down: the bottom `DEMOTE`, but at most a quarter of the group (`floor(size / 4)`), so any group of 20 or more moves 5 down (Mr. Tang asked 2026-11-19 for the top 10 to move up each week; the small-group rule was a third and a sixth before); a tie across the line spares everyone tied with the student just above it, except that 0 XP is never spared (0 XP counts as the bottom). Nobody moves down from Iron or up from Challenger; a jump of two from Grandmasters stops at Challenger. A week with no group rows (nobody read) needs no settling.

**`/state` `league`**: `{ week_start, tier: { id, name }, group_size, rows: [{ rank, username, xp, me, zone: up2 | up | down | stay }], my_rank, promote_line, podium_line, demote_line, last_result }`. Rows are the whole group, XP descending then username, 0 XP rows included. `zone` is where the row would move if the week ended now (`up2` two ranks, `up` one; it is the real move, so a podium row in Grandmasters shows `up` and any impossible move shows `stay`: Challenger up, Iron down). `promote_line` is how many places move up (ties and 0 XP can change who), `podium_line` how many of those jump two (the Leagues tab draws its "Up two ranks" divider only when it is less than `promote_line` and two ranks up exist), `demote_line` the first place that drops (null when nobody can). `last_result` is null, or `{ week_start, from: { id, name }, to: { id, name }, moved: up | down | stay, steps }` for the last settled week (`steps` 2 after a podium jump: "You jumped up two ranks to ..."). Usernames only.

**UI.** `leagueBlock` in `ui/road.js`: the rank badge (`badgeSvg` from `ui/badges.js`) and name, "You moved up to Silver" or "You dropped to Bronze" after a move, a marker on the promote and demote rows. Not browser-checked.

## Practice

Practice is a section of the Learning Road for a student who wants a break from the road, or who has finished it. It builds sessions on the student's weakest units. XP only: no ledger rows, `rewardFor` is never called, and `/finish` returns `paid: false, reward_cents: 0`. Every number is in the `PRACTICE` object in `practice.js`.

**Opens** once the student has a row in `learn_answers` for the current world (they have finished a level). Any number of sessions a day.

**Weak units.** For each unit with answered questions: wrong share = wrong first answers / answered (`learn_answers.first_correct`); ties go to the lower average `learn_review` box, then content order (`weakOrder`, pure). The 3 weakest (`WEAK_UNITS`) make the pool: every question the student has met (in `learn_answers` or `learn_review`) in them. If a mode needs more than the pool holds (5 distinct words for a match, 10 questions for the others), the next weakest units are added one at a time.

**Order is seeded, never random.** `shuffle(items, seed)` is a Fisher-Yates driven by sha256; the seed is a hash of (player id, world id, day, session number). Same inputs, same order. No `Math.random`, no `Date.now`; time comes from `k.clock`.

**Modes** rotate by the number of the student's sessions: session `n` plays `MODES[n % 3]` = match, climb, timed. `/state` says which is next. (A student who has met fewer than 3 words plays an XP Climb in a match turn.)
- **match**: 5 word/meaning pairs from the pool's `terms` (deduped by word). The client gets the words and the meanings each in their own order with ids that are only places in that column; the pairing stays in the attempt state and the server checks each pick. XP 5, or 3 if there was a wrong pick; a game left unfinished earns 0.
- **climb** (shown as "XP Climb"): 3 levels of 3 steps (`CLIMB_LEVELS`, `CLIMB_STEPS`), each step `CLIMB_STEP_QUESTIONS = 2` questions from the weak-unit pool in the seeded order. XP per step is fixed, `CLIMB_XP = [[1,2,3],[2,3,4],[3,4,5]]` (total 27, under the 30 a day cap). A step is banked when both its questions are right first time; then the next starts. A wrong answer ends the climb at once and the student keeps the XP of every banked step (the wrong question goes to the daily review as in the other modes). Clearing all 9 steps, running out of pool (the pool wants `POOL_MIN = 18`) or the student stopping early also ends it with the banked XP. The rules sit in `drawStep`, `climbAnswered` and `climbXp`. An old open `pyramid` attempt in a database is read as a finished climb that keeps the XP it banked (2 per cleared step) and is closed by finish; nothing is migrated.
- **timed**: 120 seconds on the server clock from the start (`ends_at`). One question at a time (the pool cycles). An answer at or after the end is a 409 "Time is up." Checkpoints at 3, 6 and 10 right answers give 2, 3 and 5 XP, and the XP is their sum. The student may finish early.

**Wrong answers.** A wrong first answer in practice sets that question's `learn_review` box to 0, due tomorrow, so it comes back in the daily review. A right answer leaves the box alone.

**XP and the cap.** XP goes to `learn_days` through `keep()`, so it counts for the league and keeps the day (0 XP does not keep the day). At most `DAILY_XP_CAP` = 30 practice XP a day reaches `learn_days`; the day's total is in `learn_practice_days` (migration `005_practice`). Earned XP above the cap is shown on the result but adds 0.

**Tables.** `learn_practice_days (player_id, world_id, day, xp)`. A session is a `learn_attempts` row with `level_id = 'practice:<day>:<n>'`; its `state` holds the mode, the question ids (or the pairs) and the answers so far. One session is open at a time; `/practice/start` resumes it (even after midnight) and returns the same set.

**Routes** (student; answers never leave the server).

| Route | What |
|---|---|
| `POST /api/learn/practice/start` | Opens or resumes a session. `{ mode, session, ...view }`. match: `{ pairs, terms: [{ id, term }], meanings: [{ id, meaning }], matched, wrong, done }`. climb: `{ levels, per_level, xp_steps, step, banked, over, ended, size, position, questions, xp }`. timed: `{ seconds, ends_at, server_now, over, right, answered, checkpoints, xp, question }`. 409 before a level is finished. |
| `POST /api/learn/practice/pick { term_id, meaning_id }` | match only. `{ correct, ...view }`. |
| `POST /api/learn/practice/answer { question_id, value }` | climb and timed. `{ correct, why, working?, correct_value? (when right), ...view }`. 409 for a question that is not the current one, and "Time is up." after the end; 429 as `/answer`. |
| `POST /api/learn/practice/finish` | `{ practice, mode, xp, xp_added, capped, cap, xp_today, paid: false, reward_cents: 0, day_kept, next_mode, daily, ... }`. May be called early. |

**`/state`** adds `practice: { state: locked | ready, next_mode, open, xp_today, cap }` and `weak: [unit title, ...]` (the weak units, weakest first).

**UI.** `ui/practice.js`, with the road row ("Practice your weak spots: ...", the next mode) in `ui/road.js`, and a "You've finished the road. Keep sharp with Practice" call when the road is done. It uses the lesson player's `shell()` and `askQuestion()` (`ui/player.js`). Match is two columns of buttons; climb shows one connected staircase of nine rising bars in three levels (compact at the top of the question screen, big on the intro and result); timed shows a countdown from the server's end time and a bonus bar. Checked in a browser (match, climb, timed, a phone width); the finished-road call was not.
